## 所评版本

机械的几行用脚本生成，整张贴进来（内部#196）：

```bash
.venv/bin/python3 scripts/review_prep.py --rev <所评提交> --top <顶层> --prev <上一轮所评提交>
```

它在所评提交的临时检出里跑该提交自己的 fast_check，并跑一遍不带豁免的 lint（默认参数和 fast_check 的参数组合，按告警类别计数），
比较上一轮的豁免增减（只换了 `-file` 的单列），读文档版本 / 行数 / SHA256，跑完删掉检出。
fast_check 已经机械检查过的（结构、追溯、参数表、断言编号、版本表、端口比对、句子规则），清单里不再重复。

## 外部评审（G18，用户 2026-10-06 定：每一轮评审都有）

1. 评审方另起一个外部 agent（codex 或 dsh，选法见 `docs/toolchain.md`「调用外部模型 CLI」），在**独立 worktree** 里按本模板与同一组角度独立出一份清单：
   `scripts/new_worktree.sh --detach <所评提交> dsh_review_rN`（codex 同理；不建分支，用完按脚本打印的命令删掉，内部#229）。任务说明、模板副本与输出都放它的 `runs/`。
   后台调用一律把 stdin 接到 `< /dev/null`：codex 等带 prompt 参数又没关 stdin 时会一直等输入、不报错（`keel agents` 记的坑，内部#335）。
2. 评审方合并两份清单，**逐条核实后再发**。核不实的不发，不以「未核」的形式出现在清单里。
   外部 agent 给的定级（P1 / P2 / P3）按规范原文重核，不照搬（内部#335）。
3. 每条标来源（下面条目的「来源」一行）：评审方 / 外部 agent / 两者都发现。
4. 收尾：外部 agent 的 worktree 里不留未提交的改动；结果记下后删它的 `runs/`。
