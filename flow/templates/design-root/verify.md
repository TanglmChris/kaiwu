## 验证要点

<覆盖关注点：边界条件、并发组合、背压、错误注入、LRS 第 2 节的各场景；LLD 的设计断言在仿真里开启（`CBB_ASSERT_ON`）。>

**覆盖策略**（G4，内部#200）：靠随机加覆盖收敛，不靠遍历。
- 结构开关（`*_EN`、`*_NUM` 这类改结构的参数）的每种取值都要构建；
- 主体特性在最大配置上跑足；
- 其余构建随机抽，按覆盖缺口补；
- 不在目标配置内的组合照跑，失败不挡交付，除非根因在共用逻辑。

**全仓通用规范的验证项**（内部#286）：`docs/spec-writing.md` 第 3 节的通用规则每个设计都要验，下表照抄，填覆盖情况。

| 通用规范 | 验什么 | 覆盖 |
|---|---|---|
| 握手保持 | 每个握手口逐拍查：valid 为 1 且未握手时，下一拍 valid 仍为 1、payload 不变 | 覆盖 / 部分 / 未覆盖 |
| valid 不依赖 ready | 对外接口：发布前 `make iodeps` 实测；内部汇聚口按第 3 节「汇聚口的屏蔽」的三个条件核 | |
| 汇聚口屏蔽 | 每个汇聚口：未选中的请求下一拍要么仍在参与、要么被盖住；选中与握手不同拍的口，选中后保持到握手 | |
| 活性 | 看门狗：N 拍没有任何握手即判失败，按超时归类 | |
| 写数据不等命令 | 下游模型接受先于命令到达的写数据 | |
| 功能不依赖打拍配置 | 各 TPI 模式、FIFO 直通 / 深度的取值都进构建抽样 | |
