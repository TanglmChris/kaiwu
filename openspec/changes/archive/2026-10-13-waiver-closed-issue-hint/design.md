## Context

`check_waivers.final` 先判「没放行任何违规 → 过时 FAIL」，再对还在放行的豁免查 issue 状态，已关就判 FAIL。后一支本想拦「关了却没修」，但修复交付和进 main 之间有时间差，这段时间里它把正常状态判成红，而且会卡住所有基于 main 的分支。

## Decisions

- D1 — 还在放行违规而 issue 已关：打 `note  豁免挂的 #N 已关，修复还没进本分支…`，不改退出码。修复进来后，豁免不再放行任何违规，由「过时」一支判 FAIL，逼着删掉豁免。
- D2 — 规则补位：挂着失败豁免的 issue，删豁免的提交进 main 后才关（内部#218 的例外）；PM 推 main 时把这行提示当作待办核对。「关了却没修」由规则与推 main 时的核对兜住，不再靠护栏硬拦。

## Risks / Trade-offs

- 有人关了 issue 又没修，豁免会一直放行，只出提示。缓解：规则禁止这样关；推 main 时 PM 核对这行提示；查不到 issue 状态的提示照旧。
