## ADDED Requirements

### Requirement: 流程的某一段不得报告它没有产出的产物

当流程的某一段声称产出了一个文件时，它 MUST 在返回该文件路径之前确认该文件确实
存在。产物缺失时 MUST 当场失败，并指明**是哪一段、本该产出什么、外部工具实际说了
什么**；MUST NOT 把一个未经核实的路径作为结果返回。

这条与「缺少必需输入时必须报出真正的原因」是同一条原则的两端：那条管**消费侧**
（下游缺输入时别让用户面对外部工具的内部错误），这条管**生产侧**（上游别把没做成
的事报成做成了）。生产侧的失效更难诊断，因为故障会在另一个模块、更晚的时刻才浮现，
而那时的错误信息指向的是消费者，不是真正的原因。

外部工具的退出码 MUST NOT 被单独当作产出成功的证据。工具可以在参数被误解、
输出被重定向、或写入被静默跳过的情况下仍以 0 退出。

#### Scenario: 外部工具以 0 退出但没有产出文件

- **WHEN** 某一段调用外部工具，工具以 0 退出，但约定的产物不存在
- **THEN** 该段 MUST 失败
- **AND** 错误 MUST 指明是哪一段、缺的是哪个文件
- **AND** 错误 MUST 包含该工具的实际输出，使参数被误解这类原因可被看见

#### Scenario: 产物确实存在

- **WHEN** 某一段调用外部工具且约定的产物确实生成
- **THEN** 该段 SHALL 正常返回该产物的路径
