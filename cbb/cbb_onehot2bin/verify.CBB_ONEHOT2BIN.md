# CBB_ONEHOT2BIN 验证

验证状态：已验证（`tb/test_CBB_ONEHOT2BIN.py`：`params.yaml` 全部 5 组参数，`DAT_W` <= 16 穷举、更宽定向加固定种子随机，逐个对照参考模型并查 A1–A3）

## 现状（2026-10-03）

`tb/test_CBB_ONEHOT2BIN.py`（cocotb）覆盖 `params.yaml` 声明的全部 5 组参数（`DAT_W` 2/5/16/32/33），全部通过。跑法（参数给全）：

```bash
make -f flow/Makefile sim DESIGN=CBB_ONEHOT2BIN PARAMS="DAT_W=33"
```

它同时是流程的 RTL 仿真 TB：动态功耗的活动率来自它的 VCD。

## 激励

- 纯组合、没有时钟（`sim.clock_signal: null`）：送一个输入、等 1 ns、采样。
- `DAT_W` <= 16（2、5、16）：全部 2^`DAT_W` 个输入穷举（16 位是 65536 个）。
- `DAT_W` = 32 / 33：全 0、全 1、首尾两位、每个单热位、每对相邻两位，再加固定种子的 2000 个随机输入（多热为主）；共约 2070 个。TB 末尾确认激励里的单热输入恰好是 `DAT_W` 个。
- `ADDR_W` 不在 `params.yaml` 里扫，取 DUT 端口的实际位宽。

## 判对错

参考模型按 spec「时序约定」的两种说法各写一份：任意输入按公式（所有为 1 的位的下标按位或）；单热 / 全 0 时用 `bit_length() - 1` 直接求下标。每个输入 `o_bin` 都要等于公式的结果（多热输入 spec 说调用方不得依赖，但输出仍由公式定义，所以也查）。

| 断言 | 怎么查 |
|---|---|
| A1 | 单热输入：`o_bin` 等于那一位的下标，且 `i_oh[o_bin] = 1` |
| A2 | `i_oh == 0` 时 `o_bin == 0` |
| A3 | 每个输入：`o_bin >> $clog2(DAT_W) == 0` |
