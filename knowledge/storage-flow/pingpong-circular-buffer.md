# 乒乓与循环 buffer（Ping-pong / Circular Buffer）

- **类别**：存储与流控
- **一句话**：当访问模式不是"先进先出"而是"**按块交替**"或"**按地址随机**"时，
  FIFO 就不合适了 —— 乒乓用两块存储换掉读写冲突，循环 buffer 用地址回绕换掉搬移。
- **典型用途**：双缓冲（一块在算、一块在收）、行缓冲（图像/卷积的滑窗）、
  重排序缓冲、乱序完成的记分板。

## 结构

### 乒乓（ping-pong / double buffering）

两块同样大小的存储，一块被写、另一块被读，**每处理完一块就交换角色**：

```
       ┌─────────┐          ┌─────────┐
写 ───►│ bank 0  │   swap   │ bank 1  │◄─── 读
       └─────────┘  ◄────►  └─────────┘
```

- 交换只是翻转一个 bank 选择位，不搬数据。
- 存储可以是单口 RAM —— **这是乒乓最大的价值**：
  用两块单口 RAM 换掉一块双口 RAM，通常更省面积和功耗。
- 代价是**存储翻倍**，且交换点必须由生产者和消费者都同意
  （一个握手或一个固定的块边界）。

推广到 N 块就是**多缓冲**（N-buffering），用来吸收生产/消费速率的抖动。

### 循环 buffer（circular / ring buffer）

一块存储 + 读写指针 + 地址回绕。**结构上和 FIFO 完全一样** ——
区别在于访问接口：

- FIFO：只能从头读、往尾写，指针由硬件维护。
- 循环 buffer：**允许按偏移随机访问**（`base + offset`），
  指针由使用者控制。

行缓冲（line buffer）是最常见的形态：存 K 行图像，
卷积窗口同时读 K 行的同一列，写入最新一行覆盖最旧一行。

### 怎么选

| 访问模式 | 用什么 |
|---|---|
| 严格先进先出 | FIFO，见 [`sync-fifo.md`](sync-fifo.md) |
| 按块交替，块内顺序 | 乒乓 |
| 滑窗，需要同时看多个历史位置 | 循环 buffer / 行缓冲 |
| 乱序写入、按 tag 取出 | 循环 buffer + 有效位（重排序缓冲） |

## 关键路径

- 乒乓：bank 选择是一个 mux，**O(1)**。地址不用回绕，
  各 bank 内是普通计数。
- 循环 buffer：地址回绕。深度是 2 的幂时是**免费的**（截位即可）；
  非 2 的幂时要 `addr == DEPTH-1 ? 0 : addr+1`，多一级比较+mux。
- 行缓冲的关键路径通常在**多路读出后的归约**（比如卷积的乘加树），
  不在缓冲本身。

## PPA 权衡

- **乒乓 vs 双口 RAM**：这是核心权衡。
  - 乒乓：2 × 单口 RAM。面积可能更小（单口 bitcell 比双口小很多），
    功耗更低，但总容量翻倍。
  - 双口：1 × 双口 RAM，容量不翻倍，但 bitcell 更大、漏电更高。
  - **分界线是工艺和容量相关的**，必须实测。本仓库**没有接 SRAM 宏**
    （`asap7_sram_0p0` 拉了但流程没用），触发器实现下这个对比意义不大。
- **N 缓冲的收益递减**：从 1 到 2 收益最大（消除读写冲突），
  2 到 3 只是吸收抖动。除非速率抖动很大，否则 N=2 就够。
- **行缓冲的深度由算法定死**（K 行就是 K 行），没有权衡空间；
  **宽度**（存一整行还是分块）才是可调维度。

## 什么时候选它 / 什么时候别用

- **生产和消费天然按块，且块边界明确** → 乒乓。
- **只有单口 RAM 可用，又要同时读写** → 乒乓（这往往是决定性理由）。
- **滑窗算法** → 行缓冲。
- **数据流是连续的、没有块边界** → FIFO，别硬凑乒乓
  （交换点不明确会引入复杂的同步逻辑）。
- **容量紧张** → 别用乒乓，它天然翻倍。改用 FIFO 或双口 RAM。

## 实现要点与坑

- **乒乓的交换时刻必须两侧一致**。最常见的 bug 是写侧已经交换、
  读侧还没交换，读到半新半旧的数据。做法：交换由一次握手触发，
  或由一个双方都能算出的固定块计数决定。
- **乒乓在块大小不整齐时会退化**：最后一块没填满也要占一整个 bank。
  流式数据要考虑这个浪费。
- **循环 buffer 深度非 2 的幂时回绕不是免费的**，
  且"满"的判断会变复杂（同 FIFO 的指针法问题，见
  [`sync-fifo.md`](sync-fifo.md)）。
- **行缓冲的边界处理**（图像第一行/最后一行）往往比缓冲本身还复杂，
  是 bug 高发区。参数化时要把边界策略（补零/复制/跳过）显式做成参数。
- **不需要 `keep_hierarchy`**：存储结构由 RAM/寄存器边界保住。
  但如果用触发器实现，综合可能把没用到的 bank 优化掉 ——
  做面积对比实验时要确认两个 bank 都还在。

## 参数化接口建议

> 接口按本仓 RTL 命名约定写（`rtl-structure-authority`，2026-09-28）：参数 `DAT_W` / `*_W` / `*_N` / `*_EN` / `SCHEME`，端口 `i_` / `o_` 前缀，握手 `i_vld/o_rdy/o_vld/i_rdy`。

```verilog
module BLOCK_BUFFER #(
    parameter DAT_W  = 32,
    parameter DEPTH  = 64,      // 单块深度
    parameter BANK_N = 2,       // 2 = 乒乓；1 = 单块循环；>2 = 多缓冲
    parameter SCHEME = 0        // 0 FF（触发器） | 1 SP_RAM（单口） | 2 DP_RAM（双口）—— 对照组
)(
    input clk, rst_n,
    input  i_wr_vld, output o_wr_rdy, input [DAT_W-1:0] i_wr_dat,
    output o_rd_vld, input  i_rd_rdy, output [DAT_W-1:0] o_rd_dat,
    input  i_swap               // BANK_N>1 时的交换触发
);
    localparam SCHEME_FF     = 0;
    localparam SCHEME_SP_RAM = 1;
    localparam SCHEME_DP_RAM = 2;
```

`SCHEME`（存储实现）档是这张卡的实验核心：**"2×单口 vs 1×双口"的分界线在哪**。
但它**依赖 SRAM 宏，本仓库目前接不了**，只能等有宏模型之后再做。

## 出处

乒乓缓冲和循环 buffer 都是没有单一出处的通用工程技术，属于教科书常识。
本卡不列具体文献 —— **宁可没有出处，也不编造引用**（见
`knowledge/CLAUDE.md` 第 2 条）。

行缓冲在图像处理/CNN 加速器文献里有大量具体实例，
但各家形态差异很大，引用时需针对具体架构确认。

## 本地实测

暂无，**且短期内价值有限**。这张卡最有价值的实验是
`MEM = SP_RAM ×2 vs DP_RAM ×1` 的面积功耗对比，
而本仓库**没有接 SRAM 宏**（见 `docs/toolchain.md`「ASAP7 的几个事实」），
用触发器实现测出来的结论无法外推。

在接上 SRAM 之前，能做的只有 `BANKS` 对控制逻辑面积的影响，
那部分开销很小，测了也说明不了什么。**优先级排在本类最后。**
