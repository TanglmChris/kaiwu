# 复位策略（Reset Strategy）

- **类别**：存储与流控
- **一句话**：**异步复位、同步释放** —— 断言不需要时钟（掉电也能复位），
  释放必须对齐时钟（否则恢复时刻的亚稳态会让各触发器在不同拍出复位）。
- **典型用途**：所有时序设计。这是少数"几乎没有权衡、直接照做"的选择。

## 结构

### 三种做法

| | 断言 | 释放 | 问题 |
|---|---|---|---|
| 纯同步复位 | 需要时钟 | 对齐时钟 | 没时钟就复不了位；复位信号进数据路径，占逻辑 |
| 纯异步复位 | 立即 | 立即 | **释放时违反 recovery/removal，触发器亚稳态** |
| 异步复位同步释放 | 立即 | 对齐时钟 | 无 —— 标准答案 |

### 异步复位同步释放（reset synchronizer）

```
                  ┌───┐   ┌───┐
        1'b1 ─────►│D Q│──►│D Q│───► rst_n_sync（送给本域所有触发器的异步复位口）
                   │   │   │   │
   rst_n_async ───►│CLR│──►│CLR│
                   └───┘   └───┘
                     ▲ clk   ▲ clk
```

- `rst_n_async` 拉低 → 两个触发器立刻异步清零 → `rst_n_sync` 立刻拉低。
  **断言是异步的**，不需要时钟。
- `rst_n_async` 释放 → 常数 1 顺着两级触发器走两拍 → `rst_n_sync` 在
  时钟边沿对齐地拉高。**释放是同步的**。

第一级触发器可能因释放时刻违反 recovery 而亚稳，第二级给它一拍衰减 ——
这就是一个复用了两级同步器的结构，见
[`cdc-synchronizers.md`](cdc-synchronizers.md)。

**每个时钟域各需要一个复位同步器。** 一个域的 `rst_n_sync` 不能直接给
另一个域用 —— 那就是一根未同步的跨域信号。

## 关键路径

- 复位网络本身通常不在数据关键路径上，但它**扇出极大**（全芯片触发器），
  是布局布线阶段的重点对象，往往需要专门的缓冲树。
- **同步复位会进数据路径**：`always @(posedge clk) if (!rst_n) q <= 0; else q <= d;`
  会把复位综合进 D 端的逻辑锥，增加一级。位宽大、复位信号多的地方
  这个开销是实打实的。
- 异步复位走触发器的专用 CLR 口，**不占数据路径**。这是它在延时上的优势。

## PPA 权衡

- **面积**：ASIC 库里带异步复位的触发器通常比不带的略大；
  但同步复位把逻辑推进数据路径，往往更贵。**总体上异步复位更省**。
- **不是所有触发器都需要复位。** 数据通路上的流水寄存器往往
  可以不复位（反正头几拍的数据是垃圾，靠 valid 挡住就行），
  只复位控制状态。**这能显著减小复位网络的扇出和面积**，
  是一个真实的优化点。
- **FPGA 上结论相反**：Xilinx/Intel 的触发器复位资源是免费的，
  但全局复位会破坏 SRL/BRAM 推断。FPGA 上的最佳实践是**尽量少复位**。
  ASIC 和 FPGA 在这里的结论不一样，别照搬。

## 什么时候选它 / 什么时候别用

- **默认**：异步复位同步释放。没有理由就用它。
- **纯同步复位**：只在明确知道时钟一定先于复位到位、且工艺库触发器
  不带异步复位口时考虑。
- **纯异步复位（不同步释放）**：**不要用**。这不是权衡，是 bug。
- **不复位**：数据通路寄存器可以，控制状态机绝对不行。

## 实现要点与坑

- **释放的同步是必需的，断言的异步是可选的** —— 很多人记反了。
  如果不需要"无时钟也能复位"，纯同步复位也是合法选择；
  但只要用了异步断言，**就必须同步释放**。
- **recovery / removal 是真实的时序检查**，和 setup/hold 同等重要。
  STA 必须做（OpenSTA 支持 `report_checks -path_delay min_max` 覆盖）。
  ⚠️ **本仓库的情况以前在这里写错了，归因错了一层。** 原文说
  「`run_sta.py` 只做 `-path_delay max`，recovery/removal 没有检查 ——
  这是当前流程的一个盲区」。两句都不成立（2026-09-20 核）：
  - `run_sta.py` 自 内部#24 落地起 **min 侧也在做**（`worst_slack -min` 进记录的
    `sta.hold_slack_ns`）；recovery 本来就在 max 分析的 `asynchronous` 组里，
    tcl 里还专门为它写了注释（`run_sta.py:121`）。**检查一直在跑。**
  - 真正的缺口在 **RTL**：四个设计根全部用异步复位，而**一个复位释放同步器都没有**
    （全仓 grep 0 命中，`rst_n` 是主输入直连全部触发器的 `RESETN`）。
    没有同步器时，释放时刻相对时钟沿是任意的 —— STA 报出的任何 recovery/removal
    数字都只是在复述「你在约束里假设它什么时候到」。
  - 实测坐实：三个设计（8 / 145 / 2433 个触发器）的 `worst_slack -min`
    **一位不差地相同**（`-0.021162700663102926`），因为最差 min 路径永远是
    理想驱动的 `rst_n → removal`，那就是库里 DFF 的 removal 时间，**与电路无关**。
  - **「检查没跑」与「检查跑了但问的问题没有意义」是两种完全不同的缺口**，
    修法也不同：前者改流程，后者改 RTL。写成前者会让人去改一个没坏的东西。
  - **2026-09-21 决定：不补同步器**，把它登记为已知的 RTL 缺口。理由是本项目的
    目标是 PPA 对比实验，不是流片 —— 补同步器会改变每个设计的触发器数与面积、
    必然换代、要全量重跑，而换来的 recovery/removal 数字不进任何一条结论。
    **代价是明确的**：这批设计的 min 侧只有域内 reg→reg 的 hold 余量是有意义的
    （内部#24 已经把口径收到那里），`rst_n` 起点那条路径上的任何数字都不要引用。
    真要流片或做复位收敛分析时，这是第一件要补的事。
  见本仓 内部#41（已关闭，
  结论即上面这条）。
- **复位信号扇出到不同域必须各自同步**，直连是 CDC 错误。
- **复位期间的初值必须和仿真一致**：ASIC 触发器上电是 X，
  没被复位的触发器在门级仿真里会传播 X。RTL 仿真常常因为初值为 0 而掩盖问题。
- **异步复位的毛刺是致命的**：复位树上任何组合逻辑产生的毛刺
  都会直接清掉触发器。复位路径上尽量不放组合逻辑。
- **不需要 `keep_hierarchy`**。但复位同步器和普通两级同步器一样，
  要防止综合把它优化/retiming 掉。

## 参数化接口建议

> 接口按本仓 RTL 命名约定写（`rtl-structure-authority`，2026-09-28）：参数 `DAT_W` / `*_W` / `*_N` / `*_EN` / `SCHEME`，端口 `i_` / `o_` 前缀，握手 `i_vld/o_rdy/o_vld/i_rdy`。

```verilog
module RESET_SYNC #(
    parameter SYNC_STAGES   = 2,
    parameter ACTIVE_LOW_EN = 1
)(input clk, input i_arst, output o_srst);   // 异步复位进，同步释放的复位出
parameter RST_SCHEME = 0         // 0 ASYNC（异步断言同步释放） | 1 SYNC（纯同步） | 2 NONE（数据通路不复位）
localparam RST_SCHEME_ASYNC = 0;
localparam RST_SCHEME_SYNC  = 1;
localparam RST_SCHEME_NONE  = 2;
```

设计模块本身建议把复位方式做成参数，便于对照：

```verilog
parameter RESET_STYLE = "ASYNC"   // ASYNC（异步断言同步释放）| SYNC（纯同步）| NONE（数据通路不复位）
```

`NONE` 档不是凑数：**"哪些寄存器可以不复位"是一个能测出面积差异的真问题**，
尤其在深流水设计上。

## 本地实测

暂无。可测的维度是 `RESET_STYLE`（ASYNC / SYNC / NONE）对面积和关键路径
的影响，用一个带存储阵列复位开关的 FIFO 构件（`RST_EN` = 0 / 1 是存储阵列复位与否）就能做，
**成本很低**。

但要注意：这组实验**只能给出面积和数据路径延时的差异，不能验证复位设计本身的
时序正确性** —— 不是因为 STA 没做 recovery/removal（它做了，见上面「实现要点与坑」
那条更正），而是因为**这批 RTL 没有复位释放同步器**，那个检查问的问题本身没有意义。
真要验复位时序，得先加同步器（本仓
内部#41，待定），
那之后 `RESET_STYLE` 这组实验才有第三个可读的维度。
