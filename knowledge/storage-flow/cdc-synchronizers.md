# CDC 同步器族（Clock Domain Crossing Synchronizers）

- **类别**：存储与流控
- **一句话**：跨时钟域没有"安全的组合逻辑"，只有**一次只过一根线**（两级同步器）
  和**过一组线要先冻住**（握手 / 格雷码 / 异步 FIFO）两类办法。
- **典型用途**：控制信号跨域、脉冲跨域、多位数据跨域、复位跨域。

## 结构

### 问题的本质

源域信号相对目标域时钟是异步的，会违反建立/保持窗口，
目标域触发器进入**亚稳态**：输出在一段不确定的时间里既不是 0 也不是 1。
亚稳态**不能被消除，只能被降低概率**（MTBF 是指数级改善的）。

危险不止于此：亚稳态的输出被下游**不同路径**采样时，可能**得到不同的值** ——
一条线同时被读成 0 和 1，逻辑彻底崩坏。这是"必须先同步再扇出"的理由。

### 1. 两级同步器（single-bit only）

```
src_sig ──►│D Q│──►│D Q│──► dst_sig
           └───┘   └───┘
            (dst_clk 域，两拍)
```

第一级大概率进亚稳态，第二级给它一整个周期衰减。

**铁律：只能过单根线。** 多根线各配一个两级同步器**是错的** ——
每根线的亚稳态衰减时间独立，它们会在不同的拍到达目标域，
目标域看到的组合是源域从未出现过的中间态。

**适用条件**：信号变化足够慢（至少稳定 2~3 个目标域周期），
否则会漏采（见下面的脉冲同步）。

### 2. 脉冲同步器（源域窄脉冲 → 目标域）

慢时钟域采不到快时钟域的单拍脉冲。做法是**先把脉冲变成电平**：

- **toggle 同步器**：源域每来一个脉冲就翻转一个电平，
  目标域同步后做边沿检测（异或相邻两拍）还原成脉冲。
- **限制**：源域两个脉冲之间必须间隔足够长（够目标域采到翻转），
  否则丢脉冲。要背靠背就得上握手或异步 FIFO。

### 3. 握手同步器（多位数据，低吞吐）

```
源域: 摆好 data，拉 req ──同步──► 目标域: 采 data，拉 ack
源域: 收到 ack，撤 req ◄──同步── 目标域: 撤 ack
```

**data 本身不加同步器**，靠 `req` 保证它在被采样时已经稳定了若干拍。
这叫"冻住"：数据线在握手窗口里不动，所以不存在亚稳态问题。

代价是**每笔数据要两个来回的同步延迟**（约 2×(2+2) 拍），吞吐很低。

### 4. 格雷码指针（多位、单调递增）

多位数据跨域的另一条路：**保证任意两个相邻值之间只有一位变化**。
这样即使采样时刻落在变化点上，采到的要么是旧值要么是新值，
不会是第三个值。

只对**单调递增/递减的计数器**成立，正是 FIFO 指针的形态 ——
见 [`async-fifo.md`](async-fifo.md)。

### 5. 异步 FIFO（多位、高吞吐）

握手法的吞吐太低时的标准答案。见 [`async-fifo.md`](async-fifo.md)。

## 关键路径

CDC 同步器本身在目标域是纯触发器链，**不在关键路径上**。
真正的时序问题在别处：

- **源域到同步器第一级的路径要做 `set_max_delay` 约束**，否则
  综合/P&R 认为它是异步路径而完全不管，源域的数据线可能长得离谱，
  导致数据比 `req` 晚到 —— 握手法就此失效。
- 同步器两级之间**必须相邻放置**（`ASYNC_REG` 之类的属性），
  否则第一级的亚稳态还没衰减完就被第二级采了。

## PPA 权衡

- 面积可以忽略（每根线两个触发器）。
- **延迟是主要代价**：两级同步器 2~3 拍；握手法一个来回 8 拍上下；
  异步 FIFO 的空/满标志也有 2~3 拍的滞后（所以它们是**保守**的：
  可能报满而实际不满，绝不会反过来）。
- **别为了省延迟减到一级同步器**。MTBF 会掉几个数量级，
  这是可靠性问题不是性能权衡。

## 什么时候选它 / 什么时候别用

| 场景 | 选什么 |
|---|---|
| 单根慢变化控制信号 | 两级同步器 |
| 单拍脉冲，间隔足够 | toggle 同步器 |
| 多位数据，吞吐低 | 握手 |
| 多位数据，吞吐高 | 异步 FIFO |
| 单调计数器 | 格雷码 + 两级同步器 |
| 复位跨域 | 异步复位同步释放，见 [`reset-strategy.md`](reset-strategy.md) |

**永远不要**：给多位总线的每一位配一个两级同步器。这是 CDC 里最经典、
后果最严重的错误 —— 仿真常常发现不了，硅上偶发。

## 实现要点与坑

- **同步器必须在 RTL 里可识别**：约定命名（`*_sync_ff`）或加属性，
  CDC 检查工具和 P&R 都靠它识别。乱写会导致工具把两级优化成一级
  （功能等价！但可靠性没了）。
- **必须加 `(* ASYNC_REG *)` 或等价属性**，同时在 SDC 里对跨域路径
  `set_false_path` 或 `set_max_delay -datapath_only`。
  **只做 RTL 不做约束等于没做。**
- **仿真发现不了 CDC bug**：RTL 仿真里没有亚稳态模型，跨域采样看起来永远正确。
  必须靠 CDC 静态检查工具（Spyglass CDC / Questa CDC），
  或至少靠随机延迟注入。**本仓库当前没有 CDC 检查能力**，
  写异步设计时这一点要心里有数。
- **收敛(convergence)问题**：两根各自正确同步的信号，在目标域汇聚到同一处
  组合逻辑时，仍然会因为到达拍数不同而产生毛刺态。同步后要么再打一拍，
  要么保证下游对中间态免疫。
- **不需要 `keep_hierarchy`，但需要防优化**：两级同步器功能上等价于
  "延迟两拍"，综合可能做 retiming 把它挪走。属性 + 约束是防线。

## 参数化接口建议

> 接口按本仓 RTL 命名约定写（`rtl-structure-authority`，2026-09-28）：参数 `DAT_W` / `*_W` / `*_N` / `*_EN` / `SCHEME`，端口 `i_` / `o_` 前缀，握手 `i_vld/o_rdy/o_vld/i_rdy`。

```verilog
module SYNC_2FF #(
    parameter DAT_W       = 1,        // 只允许 1；>1 时应当 elaborate 报错
    parameter SYNC_STAGES = 2,        // 2 或 3；高可靠场景用 3
    parameter INIT        = 1'b0
)(input dst_clk, dst_rst_n, input [DAT_W-1:0] i_dat, output [DAT_W-1:0] o_dat);
```

**`DAT_W > 1` 时应该直接报错而不是默默例化多个同步器** —— 把最危险的
误用挡在 elaborate 阶段。这是参数化能提供的最大价值。

## 本地实测

暂无，**而且短期内也不该有**。CDC 的正确性不体现在 PPA 指标上：
一个错误的 CDC 设计跑出来的面积/延时/功耗数字和正确的没有区别。
这张卡的价值是"别写错"，不是"测多快"。

真要做实验，唯一有意义的维度是**同步器级数对目标域时序的影响**
（2 级 vs 3 级），但那也几乎测不出差别。优先级低。
