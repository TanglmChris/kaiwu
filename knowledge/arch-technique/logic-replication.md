# 逻辑复制解 fanout（Logic / Register Replication）

- **类别**：架构范式与技巧
- **一句话**：一根线要驱动几百个负载时，与其堆一棵缓冲树，
  不如**把驱动它的那点逻辑复制几份**，各管一片 ——
  但综合工具的 `opt_merge` 会把你复制出来的东西合并回去。
- **典型用途**：全局 stall / flush / enable、
  复位树、模式配置位、
  仲裁 grant 扇出到很宽的数据通路、
  一个寄存器的输出喂遍整个数据通路。

## 结构

### 问题：扇出的代价

一个门驱动 K 个负载时，负载电容 ≈ K × 单个输入管脚电容。
延时大致按 `t = t_intrinsic + R_drive × C_load` 走，**随 K 线性增长**。
标准解法是插缓冲树：延时降到 O(log K)，代价是缓冲器面积和它们自己的功耗。

### 复制：另一条路

如果驱动这根线的是一小块组合逻辑或一个寄存器，
**把它复制 M 份**，每份只驱动 K/M 个负载：

```
复制前：  [logic] ──────────┬── 200 个负载
复制后：  [logic] ── 50     （4 份，各自靠近自己那片负载）
          [logic] ── 50
          [logic] ── 50
          [logic] ── 50
```

- 每份的负载降到 K/M，延时线性下降。
- **额外好处（本地看不见）**：4 份可以被摆在各自负载附近，
  长连线也一起省了。缓冲树做不到这一点 ——
  它仍然要把信号从一个点送到四面八方。

### 复制 vs 缓冲：怎么选

| | 缓冲树 | 复制 |
|---|---|---|
| 面积 | 缓冲器 | M 份逻辑 |
| 延时 | O(log K) | K/M 的负载 |
| 连线 | 一个源点辐射 | **可以就近摆放** |
| 谁来做 | 工具自动 | **通常要手工** |
| 适用 | 驱动逻辑很大 | **驱动逻辑很小**（一个寄存器、几个门）|

**判据很简单：被复制的逻辑越小，复制越划算。**
复制一个触发器（register duplication）几乎总是可行的；
复制一整个加法器就不是这个技巧了。

### 寄存器复制是最常见的形态

```verilog
(* keep *) reg stall_a, stall_b, stall_c, stall_d;
always @(posedge clk) begin
    stall_a <= stall_next;   // 四个副本，同一个次态
    stall_b <= stall_next;
    stall_c <= stall_next;
    stall_d <= stall_next;
end
```

四个触发器行为完全相同，各驱动一片。
**这正是 `opt_merge` 会合并掉的东西**（见下）。

## ⚠️ 工具会把复制合并回去（2026-09-07 核实）

yosys 的 `opt` 里包含 `opt_merge`，其文档原文：

> "This pass identifies cells with identical type and input signals.
> Such cells are then merged to one cell."

上面那四个触发器**类型相同、输入信号相同** —— 教科书式的合并目标。
`synth` 的默认脚本里 `opt` 出现多次，所以**手写的复制默认活不下来**。

保住它的办法：
- 在信号上加 `(* keep *)`（yosys 会保留被标记的线网和它的驱动）；
- 或者把每个副本放进独立模块并在 `params.yaml` 的 `keep_hierarchy:` 里声明保层级；
- DC 那边对应的是 `set_dont_touch` / `set_size_only`。

**验证方法是数触发器**：写了 4 个副本却只综合出 1 个，
就说明被合并了。**这和 `docs/pitfalls.md` 的 P-3是同一类失败模式** ——
功能完全正确，结构意图没了，而且**不报任何警告**。

## 关键路径

- 复制把负载从 K 降到 K/M，**延时按负载线性下降**（在 liberty 的
  `C_load` 项上）。
- 但复制**不改变**驱动逻辑本身的深度 —— 它只解决扇出，不解决深度。
  深度问题去看 [`pipelining.md`](pipelining.md) /
  [`late-arriving-signal.md`](late-arriving-signal.md)。
- **本地触发器驱动档位很有限**（本库 SEQ 家族只有
  `DFFHQNx1/x2/x3` 与 `DFFHQx4`，非反相输出只有 x4 一档）。
  这意味着高扇出的寄存器**没有更大的档可换**，
  综合只能靠外挂缓冲 —— **复制在本地库上比在驱动档位丰富的库上更有价值**。

## PPA 权衡

- 面积：+M−1 份逻辑。对一个触发器来说是小钱，
  对一块组合逻辑来说要算账。
- 功耗：复制出来的每一份都在翻转，**动态功耗上升**；
  但缓冲树也在翻转，两者未必谁更好。⚠️ 本仓库测不了（`docs/data-credibility.md` D-1）。
- **本地流只能测到一半的收益**：
  - ✅ **管脚电容那部分是模型里有的** —— OpenSTA 从 liberty 读每个输入管脚的
    电容并累加，所以"扇出 200 比扇出 50 慢"在本地**确实测得出来**。
  - ❌ **连线电容和就近摆放那部分测不到** —— 没有 LEF / 没有 P&R /
    寄生参数为零（见 [`../README.md`](../README.md)）。
  
  所以**本地会低估复制的收益，但不是完全看不见** ——
  这一点比 [`barrel-shifter.md`](../priority-encode/barrel-shifter.md)
  那类"完全看不见"的情况好，值得区分对待。

## 什么时候选它 / 什么时候别用

- **STA 报告显示某条路径的延时被负载电容主导** → 先看这张卡。
- **被复制的是一个寄存器或几个门** → 复制，几乎无脑划算。
- **被复制的是一大块逻辑** → 别复制，让工具插缓冲。
- **扇出不大（< 20）** → 别管，工具自己会处理。
- **信号要跨很远的距离** → 复制帮不上（每份还是要送到远处），
  需要的是流水寄存器（在路上打一拍）。
- **在本仓库里** → 可以做，但**收益会被低估**（连线为零）。

## 实现要点与坑

- **合并回去是默认行为，不是意外。** 见上。**每次做复制都要数一遍
  综合后的单元数**确认它活着。这是本卡最重要的一条。
- **复制会让形式等价性检查变复杂**：一个 RTL 触发器对应四个网表触发器，
  组合等价性检查的点对点映射就不成立了。**本仓库现在没有等价性检查**
  （见 内部#22），所以这类改动是无保护的。
- **复制出来的副本必须真的等价。** 手写四份时很容易在某一份里
  写错复位值或漏掉一个条件。**用 generate 循环生成，别手抄四遍。**
- **别复制有副作用的东西。** 复制一个计数器 = 四个计数器，
  它们会一起走，看起来没事 —— 直到某一份因为局部条件不同而分岔。
  **只复制纯函数（组合逻辑）和纯寄存器（同一个次态）。**
- **复位信号的复制是特例**：复位树通常由工具/后端专门处理
  （复位是全局高扇出信号的典型），手工复制复位可能和后端流程打架。
  先问后端。见
  [`../storage-flow/reset-strategy.md`](../storage-flow/reset-strategy.md)。
- **复制和资源共享方向相反。** [`resource-sharing.md`](resource-sharing.md)
  在合并，这张卡在拆分。同一个设计里两者作用于不同的对象
  （共享作用于贵的算子，复制作用于高扇出的小逻辑），
  但**如果工具的 `share` 把你要复制的东西合并了，就会打架** ——
  这时用 `(* keep *)` 而不是关掉 `share`。

## 参数化接口建议

> 接口按本仓 RTL 命名约定写（`rtl-structure-authority`，2026-09-28）：参数 `DAT_W` / `*_W` / `*_N` / `*_EN` / `SCHEME`，端口 `i_` / `o_` 前缀，握手 `i_vld/o_rdy/o_vld/i_rdy`。

```verilog
module FANOUT_DEMO #(
    parameter LOAD_N = 256,       // 负载数量
    parameter REPL_N = 1          // 驱动逻辑复制份数
)(
    input clk, rst_n,
    input               i_ctrl,
    input  [LOAD_N-1:0] i_dat,
    output [LOAD_N-1:0] o_dat
);
    genvar i;
    generate for (i = 0; i < REPL_N; i = i + 1) begin : g_repl
        (* keep *) reg ctrl_r;                    // 没有 (* keep *) 会被合并
        always @(posedge clk) ctrl_r <= i_ctrl;
        // 每份驱动 LOAD_N/REPL_N 个负载
    end endgenerate
```

扫 `LOAD_N`（扇出）× `REPL_N`（复制份数）能画出
**"扇出—延时"曲线以及复制把它压平的效果**。
这是本地流**部分可信**的实验（管脚电容有、连线电容无），
结论要写明这个边界。

## 本地实测

暂无。**这是本类里少数几张"本地测得出至少一半"的卡**，
因为管脚电容在 liberty 里、OpenSTA 会算。

建议的实验：固定驱动逻辑，扫 `WIDTH = 32/64/128/256`（扇出）
和 `REPL = 1/2/4`，看关键路径延时。预期：

1. `REPL=1` 时延时随 `WIDTH` 上升（管脚电容累加）；
2. `REPL` 增大把曲线压平；
3. **收益会比真实版图上小**，因为连线电容和就近摆放的好处本地为零。

第 3 条应当作为结论的一部分写出来，而不是事后解释 ——
它是一条**可以预先声明、之后用 DC/P&R 验证的偏差**，
天然属于 `calibration/` 那条线。

⚠️ 跑之前先确认 `(* keep *)` 生效（数触发器），
否则三档 `REPL` 会综合成同一个东西。
