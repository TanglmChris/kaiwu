# 操作数隔离与时钟门控（Operand Isolation / Clock Gating）

- **类别**：架构范式与技巧
- **一句话**：不用的时候别让它翻转 —— 时钟门控掐掉触发器和时钟树的功耗，
  操作数隔离掐掉组合逻辑的功耗；
  **本仓库现在一个都测不了**（功耗反标失效），而且 yosys 不会自动插时钟门控。
- **典型用途**：低功耗设计的第一手段。空闲的流水级、
  按模式切换的算子、宽数据通路的旁路、
  多周期运算中不活动的那些拍。

## 结构

### 时钟门控（clock gating）

不让空闲寄存器收到时钟沿：

```
GCLK = CLK & (锁存过的 ENA)
```

**必须用集成时钟门控单元（ICG），不能用一个裸的 AND 门。**
裸 AND 的问题是 `ENA` 在时钟高电平期间变化会在 `GCLK` 上产生毛刺，
那是一个**假时钟沿**，会让下游寄存器采到错误数据 ——
这是硬件里最难查的一类 bug。ICG 内部用一个**在时钟低电平期间透明的锁存器**
先把 `ENA` 采稳，再去和时钟相与。

**本地 PDK 有 ICG（2026-09-07 核实）**：
`~/pdk/asap7_merged/asap7sc7p5t_RVT_TT.lib` 里有 10 个带
`clock_gating_integrated_cell` 属性的单元
（`ICGx1 / x2 / x3 / x4 / x5` 及若干 `DC` 变体），类型
`latch_posedge_precontrol`，管脚是 **`CLK` / `ENA` / `SE` / `GCLK`**
（`SE` 是扫描使能，见下面的坑）。

省的是两部分：
1. 触发器内部的时钟翻转功耗（即使 D 没变，时钟也在翻）；
2. **时钟树上那一段的功耗** —— 通常这部分更大。

### 操作数隔离（operand isolation）

不让空闲的**组合逻辑**看到变化的输入：

```verilog
wire [W-1:0] a_iso = en ? a : {W{1'b0}};   // 或者保持上一拍的值
wire [W-1:0] y     = expensive_op(a_iso, b_iso);
```

`en` 为低时输入静止，整块组合逻辑不翻转。
**代价是在数据通路上加了一级门** —— 它在关键路径上。

两种保持方式：
- **AND 到 0**：便宜（一个 AND），但从"上一个值"跳到 0 本身也是一次翻转。
- **保持上一拍的值**（mux 回自己）：不产生额外翻转，但要一组寄存器，贵。

数据本来就稀疏（大部分时候是 0）时用 AND；数据密集时用保持。

### 两者的分工

| | 省什么 | 代价 | 在关键路径上？ |
|---|---|---|---|
| 时钟门控 | 触发器 + 时钟树 | ICG 单元 + 使能逻辑 | **否**（在时钟侧）|
| 操作数隔离 | 组合逻辑翻转 | 一级门 × 位宽 | **是** |

**先做时钟门控**（不上关键路径），不够再考虑操作数隔离。

## ⚠️ 本仓库现状：这张卡完全测不了（2026-09-07 核实）

三个独立的原因：

1. **功耗数字本身是坏的。** 全部 28 条记录的 `dynamic_power_w` 是
   默认活动率的静态估算，VCD 反标失效（`docs/data-credibility.md` D-1）。
   **这两个技巧的全部价值都在功耗上**，所以现在测出来必然是"没区别"。
2. **yosys 没有时钟门控插入 pass。** `synth` 的默认脚本里没有任何
   clock-gating 相关的步骤（DC 那边是 `compile -gate_clock` +
   `set_clock_gating_style`）。**本地要用 ICG 只能在 RTL 里手工例化**，
   拿不到"工具自动插入"的对照。
3. **操作数隔离同理**：DC 有 `set_operand_isolation_style`，yosys 没有对应物。

**所以这是整个知识库里"技巧成熟、本地零测量能力"最彻底的一张卡。**
写它的目的不是现在做实验，是：
(a) 接 DC/PT 之后第一批要验的就是它；
(b) 提醒别在当前流程下对功耗技巧下任何结论。

## 关键路径

- 时钟门控：**不上数据关键路径**。但 `ENA` 有自己的时序要求 ——
  它必须在时钟下降沿之前稳定（ICG 内部锁存器的建立时间）。
  `ENA` 生成逻辑太深会违反这个约束，表现为一条到 ICG 的时序违例。
- 操作数隔离：**直接加一级门**在数据路径上。
  位宽 W 就是 W 个门，还有 `en` 的扇出 W。
  **在关键路径上的模块不要做操作数隔离。**

## PPA 权衡

- **时钟门控几乎总是划算**：ICG 面积小、不上关键路径、
  省的时钟树功耗随扇出线性增长。工业流程里它是默认打开的。
  唯一的成本是**使能信号的生成逻辑**和**测试性**（见坑）。
- **操作数隔离要算账**：省的组合功耗 vs 多的一级门（面积 + 延时 + 
  它自己的翻转功耗）。**块越大越划算** —— 隔离一个 32×32 乘法器有意义，
  隔离一个 8 位加法器没意义。
- 门控粒度：粗（整个模块一个 ICG）省时钟树多、控制简单；
  细（每几个触发器一个）省得更多但 ICG 单元数量涨、使能逻辑复杂。
  **通常从粗做起。**

## 什么时候选它 / 什么时候别用

- **功耗是指标** → 时钟门控是第一手段，无条件先做。
- **有明确的空闲信号**（`valid` 为低、模式不匹配、流水级气泡）→
  两者都适用，且使能信号是现成的。
- **块很大且经常空闲** → 操作数隔离。
- **块在关键路径上** → **别做操作数隔离**。
- **块很小** → 隔离的门比省下的还多，别做。
- **利用率本来就接近 100%** → 两者都无效，省不到东西。
  **先量利用率**（这一点和 [`folding-time-multiplex.md`](folding-time-multiplex.md) 一样）。
- **在本仓库里想量化收益** → **现在不行**，见上面三条。

## 实现要点与坑

- **`SE`（扫描使能）不能忘。** ICG 的 `SE` 管脚存在的唯一理由是：
  扫描测试时必须让所有寄存器都收到时钟，否则扫描链断掉。
  DFT 插入流程会接这根线；**手工例化 ICG 时忘了接 `SE`，
  结果是芯片回来测不了**。本地 PDK 的 ICG 确实有这根管脚（已核实）。
- **别用裸 AND 门做时钟门控。** 见上面的毛刺问题。写
  `assign gclk = clk & en;` 在仿真里可能"能跑"，在硅上是灾难。
- **门控时钟是一个新的时钟域吗？** 不是（同源同相），但 STA 要能识别 ——
  需要 `create_generated_clock` 或工具自动推导。
  ⚠️ **本仓库的 `flow/sta/run_sta.py` 只 `create_clock` 一个 `clk` 端口**，
  没有生成时钟的处理。手工例化 ICG 后，门控下游的路径可能**根本没被约束**，
  STA 静默地少检查一批路径。**这比测不出功耗更危险** ——
  它会给出虚假的"时序通过"。
- **使能信号的逻辑不能依赖被门控的那些寄存器**，否则时钟停了就再也起不来
  （自锁死）。这是时钟门控的经典死锁。
- **操作数隔离的隔离值影响功耗。** 隔离到 0 vs 隔离到上一个值，
  哪个省要看数据分布 —— 这本身就是一个需要 VCD 才能回答的问题，
  **正是本仓库现在答不了的那类问题**。
- **保层级（`params.yaml` 的 `keep_hierarchy:`）**：操作数隔离的 AND 门功能上是冗余的
  （`en` 为低时结果不被使用），**优化器有充分理由把它删掉**。
  要保住必须设边界或加 `(* keep *)`。这和
  [`../priority-encode/find-first-one.md`](../priority-encode/find-first-one.md)
  那批"结构 vs 功能"的问题是同一类，但更隐蔽 ——
  **删掉之后功能完全正确，只是省不到功耗了**，而本地又测不出功耗，
  等于完全没有反馈。

## 参数化接口建议

> 接口按本仓 RTL 命名约定写（`rtl-structure-authority`，2026-09-28）：参数 `DAT_W` / `*_W` / `*_N` / `*_EN` / `SCHEME`，端口 `i_` / `o_` 前缀，握手 `i_vld/o_rdy/o_vld/i_rdy`。

```verilog
module DP #(
    parameter DAT_W    = 32,
    parameter CG_EN    = 1,        // 1 = 例化 ICG 做时钟门控
    parameter ISO      = 0,        // 0 = 不隔离 | 1 = AND 到 0 | 2 = 保持上一拍
    parameter CG_GRAIN = 32        // 每几个触发器共用一个 ICG
)(
    input clk, rst_n, i_se,        // i_se（扫描使能）必须一路接到 ICG
    input              i_en,
    input  [DAT_W-1:0] i_dat,
    output [DAT_W-1:0] o_dat
);
```

`CG_GRAIN` 是门控粒度的旋钮。**但在功耗反标修好之前，
扫这三个参数只会得到"面积略有不同、功耗完全相同"的无意义结果。**

## 本地实测

**暂无，且当前流程下不可能有意义。** 这张卡是
`docs/data-credibility.md` D-1（功耗反标失效）影响最大的一张 ——
**它的全部价值都在那一列坏掉的数字上。**

接 VCS/DC/PT 之后的第一批实验应当包含：

1. **时钟门控的收益**：同一份 RTL，`compile -gate_clock` 打开/关闭，
   比动态功耗。这也顺带验证 PT 的反标是对的
   （门控关掉时功耗应当明显更高 —— 一个有方向的预期，比绝对值好验证）。
2. **门控粒度曲线**：`CG_GRAIN` 扫参，找收益饱和点。
3. **操作数隔离的净收益**：因为它上关键路径，
   要同时看功耗降了多少、fmax 掉了多少，是个真正的多目标权衡。

在那之前，**这张卡只当设计 checklist 用，不当实验课题**。
