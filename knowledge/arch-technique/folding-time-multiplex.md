# 折叠 / 时分复用（Folding / Time-Multiplexing：面积换吞吐）

- **类别**：架构范式与技巧
- **一句话**：让一份硬件在 N 拍里干 N 件事 —— 运算单元的面积除以 N，
  但**换来的 mux、中间寄存器和控制器经常把省下的钱吃回去**，
  所以只值得折叠"贵的算子"。
- **典型用途**：迭代式除法/CORDIC、bit-serial 数据通路、
  串行乘法器、面积极紧的控制路径、
  低吞吐外设（UART、I2C、SPI）、把一个 N 抽头 FIR 折成 1 个乘法器。

## 结构

折叠是 [`parallel-unroll-cslow.md`](parallel-unroll-cslow.md) 的反操作：
并行是"把 1 份变 P 份"，折叠是"把 N 份变 1 份"。

一次折叠要配齐四样东西：

1. **一份共享的运算单元**（被折叠的那个）；
2. **输入 mux**：每拍从 N 组操作数里选一组 —— **N:1 的宽 mux，
   这是主要的隐藏成本**；
3. **中间结果的寄存器/寄存器堆**：算出来的东西要存到下次用；
4. **控制器**：一个计数器或 FSM，产生调度（第几拍做哪件事）。

### 折叠因子与账本

| | 运算单元面积 | mux + 寄存器 | 吞吐 | 延迟（拍） |
|---|---|---|---|---|
| 不折叠 | ×N | 0 | ×1 | 1 |
| 折叠 N | **×1** | **+2·N:1 mux + 状态** | **÷N** | **N** |

**成败全在第二列。**

### 判据：算子贵不贵

粗略的经验判据 —— 折叠只在**被折叠的算子面积 ≫ N:1 mux 的面积**时划算：

- **值得折叠**：乘法器、除法器、CORDIC 迭代、大位宽的比较树、
  排序网络的一级。这些算子的面积按 O(W²) 或 O(N log²N) 涨，
  远大于线性的 mux。
- **不值得折叠**：加法器、mux 本身、编码器、简单的位操作。
  把一个 32 位加法器折成 4 个 8 位周期，省下 24 位的加法器，
  却要付两个 4:1 的 32 位输入 mux + 一个进位寄存器 + 一个 2 位计数器 ——
  **多半是亏的**。
- 边界情况要实测，这正是本仓库该干的事。

### 极端形态：bit-serial

折叠因子 = 字长 W，每拍处理 1 位。

- 运算单元退化成**一个全加器 + 一个进位触发器**，面积 O(1)。
- 需要 W 拍。
- **连线只要 1 根而不是 W 根** —— 在连线主导的设计里这是真正的动机，
  历史上 bit-serial 流行正是因为布线便宜。
  ⚠️ **本仓库看不见这个好处**（连线代价为零，见
  [`../README.md`](../README.md)），所以本地流会**系统性低估 bit-serial**。
- **digit-serial** 是中间档：每拍处理 d 位，W/d 拍。d 是个干净的扫参维度。

### 已经在本知识库里的折叠

- [`../arith/division.md`](../arith/division.md)：restoring / SRT 除法
  本质就是把一棵巨大的组合树折叠成每拍一位（或几位）。
- [`../arith/cordic.md`](../arith/cordic.md)：迭代式 CORDIC 是
  把 N 级旋转折成 1 级 + N 拍；展开式 CORDIC 就是不折叠。
  **CORDIC 的"迭代 vs 展开"是折叠因子的教科书例子。**

## 关键路径

- 折叠**不改变**单个算子的组合深度 —— 但**会在它前后各加一级 mux**。
  所以折叠后的关键路径通常比不折叠时**略长**（多两级 mux），
  fmax 会小幅下降。这一点常被忽略。
- bit-serial 的关键路径极短（一个全加器），
  所以它的 fmax 可以很高 —— 但要 W 拍，**总延迟反而变差**。
- 控制器（计数器/FSM）如果和数据通路的 mux 串在一条组合路径上，
  它会成为新的关键路径。**把控制信号打一拍**通常是必要的。

## PPA 权衡

- **面积**：`N × A_算子` → `A_算子 + A_mux + A_reg + A_ctrl`。
  收益随 N 增大而饱和（因为 mux 的成本也随 N 涨，虽然是 log 或线性）。
- **吞吐**：÷N，没有例外。
- **功耗**：折叠后同一份硬件每拍处理不同数据，**翻转率显著上升**，
  单位面积功耗高；但总面积小、总能耗通常下降。
  ⚠️ **本仓库测不了**（`docs/data-credibility.md` D-1，功耗反标失效）。
- **利用率**是折叠的真正动机：如果原设计里 N 份硬件只有 1/N 的时间在用，
  折叠是纯赚。**先量利用率再决定折不折**。

## 什么时候选它 / 什么时候别用

- **吞吐富余、面积紧** → 折叠。这是它唯一的用途。
- **算子贵（乘/除/CORDIC/排序）** → 折叠收益大。
- **算子便宜（加法、逻辑）** → **别折**，mux 和控制会吃光收益。
- **吞吐已经不够** → 折叠会让它更不够，方向反了，
  去 [`pipelining.md`](pipelining.md) /
  [`parallel-unroll-cslow.md`](parallel-unroll-cslow.md)。
- **延迟敏感** → 折叠把 1 拍变成 N 拍，别用。
- **连线是瓶颈**（长距离数据搬运）→ bit/digit-serial 值得认真考虑，
  但**这个判断必须等 P&R 到位才能做**，本地流看不见。
- **N 路数据其实互相独立且都要算** → 那不是折叠的场景，
  折叠是"同一件事分几拍做"，不是"几件事排队做"。

## 实现要点与坑

- **调度和数据通路必须一起改，这是折叠最容易出错的地方。**
  控制器说"第 2 拍做乘法"，数据通路的 mux 得在第 2 拍选对操作数 ——
  两边的拍数对不上是典型 bug，而且往往只在某个特定折叠因子下才错。
  **`FOLD` 的每一档都要跑一遍功能仿真**，不能只测一档。
- **中间结果的存储容易被低估。** 折叠 N 次意味着有最多 N 组中间值要存。
  如果这些值很宽，寄存器堆的面积可能超过省下来的算子。
  **算账时必须把它算进去。**
- **必须有握手。** 折叠后模块要 N 拍才出一个结果，
  上游得知道什么时候能送下一个、下游得知道什么时候有效。
  这直接把这张卡推到 valid-ready 上，见
  [`backpressure-paradigms.md`](backpressure-paradigms.md) 和
  [`../storage-flow/skid-buffer.md`](../storage-flow/skid-buffer.md)。
- **保层级（`params.yaml` 的 `keep_hierarchy:`）**：折叠版和展开版**功能等价但延迟不同**，
  工具不会把它们收敛（触发器数和时序都不同），
  所以单纯比 `FOLD` 档位**不需要**边界。
  **但被折叠的那个算子内部如果还在比微架构（比如乘法器结构），
  那一层照旧要加**（`docs/pitfalls.md` 的 P-3）。
- **别把折叠因子写成"顺便改了算法"。** 常见错误是折叠版顺手改了
  舍入或饱和顺序，于是 PPA 对比里混进了功能差异。
  各档的输出必须逐位相同（只允许延迟不同）。

## 参数化接口建议

> 接口按本仓 RTL 命名约定写（`rtl-structure-authority`，2026-09-28）：参数 `DAT_W` / `*_W` / `*_N` / `*_EN` / `SCHEME`，端口 `i_` / `o_` 前缀，握手 `i_vld/o_rdy/o_vld/i_rdy`。

```verilog
module DUT #(
    parameter DAT_W  = 32,
    parameter FOLD_N = 1,      // 1 = 全展开；DAT_W = bit-serial；中间值 = digit-serial
    parameter STATIC_EN = 0    // 调度策略：0 RR（轮转） | 1 STATIC（编译期定死）；二选一写成 _EN（D16）
)(
    input  clk, rst_n,
    input  [DAT_W-1:0] i_a, i_b,
    input              i_vld,
    output             o_rdy,     // 折叠后必须有反压
    output [DAT_W-1:0] o_dat,
    output             o_vld
);
```

`FOLD_N` 是本类里**最能拉开面积差距的单个参数**（可以差一个数量级），
而且和 `PIPE_STAGES` 正交 —— 一个降面积一个升频率，
两者一起扫能画出一条完整的 PPA 曲线。

## 本地实测

暂无。**这张卡的实验被同一个前提挡住**：折叠必然是多周期 + 握手，
而现有 `flow/sim` 和记录里的 `cycles` 语义是按组合/短流水加法器设计的
（内部#7）。`arith/` 和 `storage-flow/` 两类的结尾都指向这个前提，
**这是第三次指向它**。

流程支持之后，最该做的一个实验是**用 CORDIC 或除法器扫 `FOLD`**：
它能一次回答两件事 ——
(a) 面积随 `FOLD` 的下降曲线在哪里饱和（即 mux/控制的固定成本有多大），
(b) 折叠引入的两级 mux 让 fmax 掉了多少。
这两条都是可以直接指导选型的数字。
