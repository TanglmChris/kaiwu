# 并行展开与 C-slow（Parallel Unrolling / C-Slow Retiming）

- **类别**：架构范式与技巧
- **一句话**：流水降的是**周期**，并行降的是**拍数** —— 两者是对偶的；
  而 C-slow 是专门用来对付反馈环的那一招：
  **只把寄存器数乘 C，逻辑一个不加**，代价是要有 C 路独立的数据。
- **典型用途**：吞吐不够但时钟已经到顶、
  多通道/多线程的数据通路、
  被 iteration bound 卡死的递归运算（IIR、CRC、累加器、状态机）。

## 结构

### 并行展开（unrolling / block processing）

每拍处理 P 个输入，硬件复制 P 份：

```
吞吐 ×P     面积 ×P     关键路径 不变     延迟（拍）不变
```

**关键路径不变**是重点：并行不碰组合深度，所以它在"时钟已经到顶、
再流水也没用"的时候是唯一的出路。代价是面积线性涨，
而且输入输出的位宽也要 ×P（连线代价，本地流看不见）。

**并行和流水可以叠加**：先展开 P 份再各自流水 N 级，
吞吐 = P × f_clk。两者不冲突，因为一个降周期一个降拍数。

### 展开反馈环 = look-ahead

对递归 `y[n] = f(y[n-1], x[n])`，展开两步：

```
y[n] = f(f(y[n-2], x[n-1]), x[n])
```

**环上的组合延时翻倍，但环上仍然只有 1 个寄存器？** 不是 ——
展开之后一次迭代处理两个样本，等效于环的"每样本延时"减半。
把 `f∘f` 预先化简（常数系数时可以合并成一个更浅的函数），
就真正降低了 iteration bound。这条路径见
[`precompute-lookahead.md`](precompute-lookahead.md)，
CRC 的"一拍算 32 位"就是它的典型。

### C-slow：把寄存器数乘 C

把电路里**每一个寄存器换成 C 个串联的寄存器**，然后交错送入
**C 路互不相关的数据流**：

```
拍 0: 流 A 的第 0 步
拍 1: 流 B 的第 0 步
...
拍 C-1: 流 X 的第 0 步
拍 C:   流 A 的第 1 步
```

对每一路来说，它的"下一步"要等 C 拍才回来 —— 而这 C 拍里
硬件在替别人干活，**利用率 100%**。

为什么这能突破 iteration bound：`T∞ = 环延时 / 环上寄存器数`，
C-slow 把分母乘了 C，所以 `T∞` 除以 C。
**然后再做 retiming**（见 [`retiming.md`](retiming.md)）
把那 C 个寄存器摊到环上各处，周期就真的降下来了。

> **C-slow 的本质是硬件多线程。** 它和 GPU 的 warp 调度、
> 网络处理器的多上下文是同一个思想：用别人的活填满自己的气泡。

### 三者的账本

| | 吞吐 | 组合关键路径 | 逻辑面积 | 寄存器 | 每路延迟(拍) |
|---|---|---|---|---|---|
| 流水 N 级 | ×1（f 变高）| ÷N | ×1 | +N·W | ×N |
| 并行 P 路 | ×P | ×1 | **×P** | ×P | ×1 |
| C-slow C 路 | ×1（f 变高）| ÷C（配合 retiming）| **×1** | ×C | ×C |

**C-slow 那一列的"逻辑面积 ×1"是它全部的卖点。**

## 关键路径

- 并行：**不变**（各路互不相干）。但汇合处（比如最后要把 P 个结果相加）
  会引入一棵 O(log P) 的树。
- C-slow：C-slow 本身**不改变**关键路径，
  **必须配合 retiming 才有收益** —— 它只是把寄存器"变多"，
  还得有人去把它们挪到合适的位置。
  ⚠️ **本仓库当前不做 retiming**（见 [`retiming.md`](retiming.md)），
  所以**在本仓库里做 C-slow 只会看到面积变大、fmax 不变**。
  这不是 C-slow 无效，是流程不支持。

## PPA 权衡

- 并行 P 路：面积、功耗都 ×P，能效（每个结果多少焦耳）大致不变。
  **它买的是吞吐，不是效率。**
- C-slow：面积只涨触发器部分。如果原设计是"逻辑重、寄存器轻"
  （典型的深组合环），C=2 可能只涨 10~20% 面积就换来接近 2× 的频率。
  **这是本卡里性价比最高的一招**，前提是**真的有 C 路独立数据**。
- 并行的隐藏成本在**连线和 I/O**：P 路意味着输入带宽 ×P。
  本地流连线成本为零，**会系统性高估并行展开**（见
  [`../README.md`](../README.md) 的全库警告）。

## 什么时候选它 / 什么时候别用

- **纯前馈、吞吐不够、时钟还能提** → 先流水（
  [`pipelining.md`](pipelining.md)），便宜。
- **纯前馈、时钟已到顶** → 并行展开。
- **有反馈环、且有多路独立数据**（多通道、多流、多包）→ **C-slow**。
- **有反馈环、只有一路数据** → C-slow 用不了（没有别人的活可填），
  只能改算法：look-ahead / 展开化简（
  [`precompute-lookahead.md`](precompute-lookahead.md)）。
- **面积紧、吞吐富余** → 反过来做
  [`folding-time-multiplex.md`](folding-time-multiplex.md)。
- **数据之间有依赖**（第 n+1 个输入要用第 n 个的结果）→
  **并行展开是错的**，会算错，不是慢一点的问题。

## 实现要点与坑

- **C-slow 最大的坑：C 路数据必须真正独立。** 只要有一路会读到另一路的
  状态，交错就错了。共享的 RAM、共享的计数器、全局 flag 都是隐患。
  **这是一个架构级的前提，不是 RTL 细节。**
- **C-slow 之后延迟变成 C 倍拍数。** 对延迟敏感的路径（比如一个要
  快速关断的安全信号）不能走 C-slow 的通路。
- **并行展开的边界处理**：数据总数不是 P 的整数倍时最后一组要补齐，
  补的值必须是无害的（加法补 0、比较补极值）。**这是必测点，
  而且随机激励打不中"恰好差 1 个"的情况。**
- **展开会不会被工具优化掉？** 并行展开是 P 份**独立**硬件，
  工具没有理由合并它们（输入不同）—— 但如果 P 路输入在测试中恰好相同
  （比如激励写成了同一个信号扇出 P 份），综合会把它们合并成一份，
  面积测出来只有 1/P。**这是本仓库很容易踩的测量陷阱**：
  参数化 testbench 时要保证 P 路输入是真正不同的端口。
- **C-slow 的验证**：交错之后波形很难读。建议给每路数据带一个 tag，
  在输出端断言"tag 按 C 循环、且每路的序号单调"。
- **保层级（`params.yaml` 的 `keep_hierarchy:`）**：并行展开的 P 份如果放在同一个模块里，
  ABC 有机会跨路重组（尤其当 P 路共享部分输入时）。
  做 P 的扫参对比时要设边界，否则面积不会按 P 线性涨 ——
  **"面积没按 P 涨"是这个实验里最明确的翻车信号**
  （`docs/pitfalls.md` 的 P-3）。

## 参数化接口建议

> 接口按本仓 RTL 命名约定写（`rtl-structure-authority`，2026-09-28）：参数 `DAT_W` / `*_W` / `*_N` / `*_EN` / `SCHEME`，端口 `i_` / `o_` 前缀，握手 `i_vld/o_rdy/o_vld/i_rdy`。

```verilog
module DUT #(
    parameter DAT_W       = 32,
    parameter PAR_N       = 1,     // 并行路数 P
    parameter CSLOW_N     = 1,     // C-slow 因子 C（1 = 不用）
    parameter PIPE_STAGES = 0
)(
    input clk, rst_n,
    input  [PAR_N*DAT_W-1:0] i_dat,    // P 路必须是真正独立的输入
    input  [PAR_N-1:0]       i_vld,
    output [PAR_N*DAT_W-1:0] o_dat,
    output [PAR_N-1:0]       o_vld
);
```

`PAR_N` / `CSLOW_N` / `PIPE_STAGES` 三个维度正交，**可以在一次扫参里
把"提吞吐的三条路"全测出来**，这是本类里少见的干净三维实验。
但见下面的实测说明。

## 本地实测

暂无，**而且三个维度里只有 `PAR` 现在能测**：

- **`PAR`（并行展开）可以测**：纯组合复制，
  面积应当接近线性涨、关键路径不变。**这个实验的真实价值是当
  `keep_hierarchy` 的检验器** —— 面积没按 P 涨就说明结构被合并了。
  连线代价为零会让本地流高估并行的吸引力，这点要在结论里写明。
- **`CSLOW` 现在测不出收益**：它必须配 retiming 才降周期，
  而本仓库的流程不做 retiming（[`retiming.md`](retiming.md) 已核实）。
  现在跑只会看到"面积涨、fmax 不变"，**那是流程的结论不是设计的结论**，
  不要写进记录当成 C-slow 的评价。
- **`PIPE_STAGES` 已经有数据**，见
  [`pipelining.md`](pipelining.md) 的本地实测。
