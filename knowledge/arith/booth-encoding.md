# Booth 编码（Booth / Modified Booth Recoding）

- **类别**：算术单元
- **一句话**：把乘数重新编码成带负号的数字，让部分积的**行数减半**，
  顺带天然处理有符号数。
- **典型用途**：所有大位宽并行乘法器的第一级；MAC；有符号乘法。

## 结构

朴素乘法每个乘数位产生一行部分积，n 位就是 n 行。Booth 的观察是：
连续的一串 1（比如 `0111` = 7）可以写成 `1000 - 1` = 8 − 1，
**一串加法换成一次加、一次减**。

- **radix-2 Booth**：看相邻两位 `(b[i], b[i-1])`，得到操作 {0, +A, −A}。
  它对**数据相关**的串 1 有效，但在并行乘法器里行数并没有减少，价值主要在
  有符号数处理，实际很少单独用。
- **radix-4（Modified Booth，MacSorley 1961）**：**这才是工程上说的 Booth。**
  每次看**重叠的 3 位** `(b[2i+1], b[2i], b[2i-1])`，编码成数字集
  `{−2, −1, 0, +1, +2}`：

  | b[2i+1] b[2i] b[2i-1] | 部分积 |
  |---|---|
  | 000 / 111 | 0 |
  | 001 / 010 | +A |
  | 011 | +2A |
  | 100 | −2A |
  | 101 / 110 | −A |

  这些倍数全都是**免费的**：±A 是原值，±2A 是左移一位，负号是取反加一。
  于是 n 位乘数只产生 **⌈n/2⌉+1 行**部分积 —— **行数减半**。
  注意 `b[-1]` 恒为 0，是编码窗口的起始补位。

- **radix-8**：数字集 `{−4…+4}`，行数降到 n/3。但 **±3A 不是移位能得到的**，
  必须预先算一次 `A + 2A`，多一个加法器和一级延时。通常不划算，除非位宽很大。

## 关键路径

Booth 本身不在关键路径上产生长链 —— 编码器只看 3 位，是常数级。
它的价值是**间接的**：行数从 n 减到 n/2，压缩树的级数少一到两级
（高度按 ×2/3 缩，32 行→16 行大约省 1.7 级）。

代价是每一行部分积从"一个 AND 门"变成"一个 5 选 1 多路器"（选 0/±A/±2A），
所以**部分积生成这一级的延时变长了**。净收益 = 省下的压缩级数 − 多出的选择器延时。

## PPA 权衡

- **面积**：行数减半省下大量压缩单元，但多了编码器和每行的选择器。
  位宽大时净省，位宽小（≲16）时可能净亏。
- **延时**：位宽大时净赚。
- **功耗**：**这里有个反直觉的坑。** Booth 常常**不省功耗甚至更费**：
  选择器比 AND 门翻转更多，负数行的取反引入大量翻转，且部分积矩阵变得
  更"随机"、毛刺更多。文献里 Booth 省功耗的结论多来自面积减小，
  而活动率上升会抵消一部分。**必须用真实激励的 VCD 反标才测得出来**，
  静态估算会给你一个乐观的错觉。
- 行业惯例：位宽 ≥ 16 的有符号乘法器，radix-4 Booth 基本是默认选择。

## 什么时候选它 / 什么时候别用

- **有符号乘法、位宽 ≥ 16**：用 radix-4。它对二进制补码是天然正确的，
  不需要额外的符号修正逻辑，这一点常被低估。
- **无符号、位宽小（≤ 8）**：别用，编码开销吃掉收益。
- **乘数是常数**：完全别用，改走 `constant-multiplication.md` 的 CSD 路线。
- **功耗是主要指标**：先测再说，别假设 Booth 更省。

## 实现要点与坑

- **符号扩展会吃掉你省下的行数。** 负的部分积需要符号扩展到全宽，
  朴素做法会在矩阵顶部堆出一大片符号位，把 Booth 省下的行数又赔回去。
  标准做法是把所有符号位的常数部分预先折叠成一个常量行
  （文献里叫 sign extension prevention / 常数折叠），务必做，否则 Booth 白用。
- **负数用"取反 + 加 1"，那个 +1 要单独处理。** 通常把各行的 +1 收集起来
  塞到矩阵的空位里（hot-one 插入），不要真的做一次加法。
- **`b[-1] = 0` 别忘了**，这是编码窗口的起点。
- **结构会被综合抹平。** 和压缩树一样：Booth 乘法器功能上等价于 `a*b`，
  不在 `params.yaml` 的 `keep_hierarchy:` 里声明保层级的话，综合会重新推导（见 `docs/pitfalls.md` 的 P-3）。
  编码器和选择器要独立成模块。
- **验证要覆盖边界**：最负值（`-2^(n-1)`）、全 1、全 0、以及 ±2A 溢出的情况。
  Booth 的 bug 通常只在这些点上暴露。

## 参数化接口建议

> 接口按本仓 RTL 命名约定写（`rtl-structure-authority`，2026-09-28）：参数 `DAT_W` / `*_W` / `*_N` / `*_EN` / `SCHEME`，端口 `i_` / `o_` 前缀，握手 `i_vld/o_rdy/o_vld/i_rdy`。

```verilog
module BOOTH_ENCODER #(
    parameter DAT_W = 32,
    parameter RADIX = 4          // 2 | 4 | 8
)(input [DAT_W-1:0] i_a, i_b, output /* o_<每行的选择信号与符号> */);
```

放进本仓库时，把 `RADIX`（含 "NONE" 表示朴素 AND 生成）做成 enum，
和 `partial-product-reduction.md` 的 `SCHEME`、`COMP_SCHEME` 正交组合，
一次能扫出"编码 × 压缩策略 × 压缩器"的三维 PPA 面。
