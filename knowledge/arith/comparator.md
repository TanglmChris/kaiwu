# 比较器与绝对值（Comparator / Absolute Value）

- **类别**：算术单元
- **一句话**：相等比较是一棵 XOR-OR 归约树，大小比较其实是个前缀问题 ——
  别用"相减看符号"，那等于白付一个加法器。
- **典型用途**：地址匹配、CAM、边界检查、排序网络、仲裁、
  max/min、饱和运算、ALU 的比较指令。

## 结构

### 相等比较 `a == b`

```
ne = |(a ^ b)        // 逐位 XOR，再 OR 归约
eq = ~ne
```

一棵 OR 归约树，O(log n) 级。没有比这更好的做法。

### 大小比较 `a > b`

朴素想法是算 `a − b` 再看符号位 —— **能用但浪费**：你付了一个完整加法器
（含全宽进位链），却只要一位输出。

正确的看法是：大小比较**本身就是一个前缀问题**。从高位往低位看，
第一个不相等的位决定结果。定义逐位信号：

```
gt[i] = a[i] & ~b[i]     // 这一位 a 大
eq[i] = ~(a[i] ^ b[i])   // 这一位相等
```

拼接算子（高位优先，可结合）：

```
(gt_hi, eq_hi) ∘ (gt_lo, eq_lo) = (gt_hi | (eq_hi & gt_lo),  eq_hi & eq_lo)
```

**和加法器的 (g, p) 算子结构完全一样** —— 所以
[`prefix-adders.md`](prefix-adders.md) 里那整套前缀网络
（Kogge-Stone / Brent-Kung / Han-Carlson…）可以原样搬过来，
连 (l, f, t) 的权衡都一样适用。

### 绝对值 / max / min

- `|a|`：`a[n-1] ? (~a + 1) : a`。那个 +1 是个全宽进位链。
  **在关键路径上时**，常用的省法是先算 `~a`，把 +1 推迟到后面某个已有的加法里
  一起做（借用别人的进位入）。
- `max(a,b)`：一次比较 + 一次 mux。比较和 mux 可以并行展开成
  "两个候选都算好，最后选" —— 见 `../arch-technique/`（预计算）。

## 关键路径

- 相等比较：**O(log n)**，归约树。
- 大小比较（前缀实现）：**O(log n)**，和前缀加法器同阶，但节点更简单
  （只有两个信号，没有和的那一路）。
- 大小比较（相减实现）：也是 O(log n)，但常数更大、面积更大。
- 绝对值：一次条件取反 + 一个 O(log n) 的增量器。

## PPA 权衡

- 专用前缀比较器比"减法 + 看符号"**面积小、功耗低**，延时相当或更好。
  差距随位宽增大。
- 相等比较非常便宜，能用相等就别用大小比较。
- **如果同一处已经需要 `a − b` 的数值结果**，那就直接用减法器的符号位，
  别再放一个比较器 —— 复用比省更重要。

## 什么时候选它 / 什么时候别用

- **只需要比较结果，不需要差值** → 专用前缀比较器。
- **既要差值又要比较** → 一个减法器搞定，别重复。
- **和常数比较** → 大幅简化，很多位直接常数折叠掉，工具做得很好，别手写。
- **一堆数里找最大** → 别做两两比较的链，用比较树（O(log k)）
  或排序网络，见 [`../priority-encode/sorting-network.md`](../priority-encode/sorting-network.md)。

## 实现要点与坑

- **这是本知识库里最容易被综合工具"做得比你好"的一类电路。** 比较器逻辑简单、
  规模小，ABC 和 DC 的布尔优化对它非常有效。**手写前缀比较器很可能打不过
  直接写 `a > b`。** 所以这张卡的正确用法是：先写 `a > b` 测一遍，
  再决定要不要手写 —— 而不是默认手写更好。
- 反过来说，**位宽很大（≥64）时手写才开始有意义**，因为工具的启发式在
  大规模上退化更明显。
- **有符号 vs 无符号**：Verilog 里 `a > b` 的符号性取决于操作数声明，
  混用 `reg`/`wire`（默认无符号）和 `signed` 是经典 bug 源。显式写清楚。
- **绝对值的边界**：补码最负值 `-2^(n-1)` 取绝对值会溢出，
  必须明确定义行为（饱和到最大正值？还是位宽加一？）。这是必测点。
- **不需要 `keep_hierarchy`**——除非你就是要比较不同的前缀网络实现，
  那就和加法器一样要加。

## 参数化接口建议

> 接口按本仓 RTL 命名约定写（`rtl-structure-authority`，2026-09-28）：参数 `DAT_W` / `*_W` / `*_N` / `*_EN` / `SCHEME`，端口 `i_` / `o_` 前缀，握手 `i_vld/o_rdy/o_vld/i_rdy`。

```verilog
module COMPARATOR #(
    parameter DAT_W     = 32,
    parameter SIGNED_EN = 0,
    parameter SCHEME    = 0          // 0 PREFIX | 1 SUBTRACT | 2 TOOL（直接写 i_a > i_b）
)(input [DAT_W-1:0] i_a, i_b, output o_gt, o_eq, o_lt);
    localparam SCHEME_PREFIX   = 0;
    localparam SCHEME_SUBTRACT = 1;
    localparam SCHEME_TOOL     = 2;
```

同样保留 `TOOL` 档做对照组。这张卡和 `constant-multiplication.md` 一样，
核心实验价值在于回答"**工具的自动优化有多强、什么时候值得手写**"，
这个问题的答案决定优化时间该投在哪里。

## 出处

比较器没有单一经典文献 —— 它的前缀结构是加法器前缀理论的直接推论。
理论基础见 [`prefix-adders.md`](prefix-adders.md) 的出处，
尤其是 Harris 的分类法（同一套 (l, f, t) 权衡完全适用）。

## 本地实测

暂无。建议和 `constant-multiplication.md` 打包成同一组实验：
两者都是纯组合、成本极低，且都在测同一件事 ——
**手写结构 vs 交给工具，分界线在哪里。**
这个结论越早拿到越值钱。
